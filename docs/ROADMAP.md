# خطة المشروع: ما بقي، والسيرفر

آخر تحديث: 2026-11-23. الفرع الحالي: `feat/farsh-reader-layout`.

## الهدف

1. أن يصل أي تحديث للمستخدمين دون انتظار نسخة جديدة من المتجر قدر الإمكان: بيانات القراءات، التخطيطات، الإعدادات، الإعلانات، وإجبار التحديث عند الحاجة.
2. إكمال المميزات الناقصة في التطبيق، مع بقاء التطبيق يعمل كاملًا دون إنترنت.
3. قاعدة ثابتة في القراءات: المحتوى العلمي يأتي من مصادر منشورة كما هي (حاليًا Quran Tajweed Engine). لا اجتهاد ولا محاذاة آلية تُعرض على أنها فروق.

## ما الذي يمكن تحديثه من السيرفر وما الذي لا يمكن

| النوع | يُحدَّث من السيرفر؟ | الطريقة |
|---|---|---|
| حزم البيانات: الفرش، الفروق المعتمدة، نصوص الروايات، جداول الصفحات، تخطيط المصحف | نعم | حزمة موقّعة تُنزَّل وتُستبدل محليًا |
| الإعدادات وتشغيل/إيقاف ميزة | نعم | Remote config |
| الإعلانات ورسائل داخل التطبيق | نعم | قائمة إعلانات |
| إجبار التحديث أو التنبيه بنسخة جديدة | نعم | أقل نسخة مدعومة لكل منصة |
| كود Dart (شاشات جديدة، منطق جديد) | لا عبر بياناتنا | المتجر، أو اختياريًا Shorebird (code push لـ Flutter) لاحقًا |
| الخطوط والصور الكبيرة | نعم كحزم | نفس آلية الحزم |

القاعدة: كل ميزة جديدة تُكتب في التطبيق بحيث يعتمد محتواها على حزمة بيانات أو إعداد، فيصير تحديثها لاحقًا من السيرفر فقط.

## المرحلة 1: السيرفر وقناة التحديثات (الأساس)

### المعمارية

```
quran/
├── app (Flutter الحالي)
├── server/          Hono + Drizzle ORM + PostgreSQL
├── admin/           React + Ant Design (Vite)
└── packages/shared  أنواع ومخطط الـAPI المشترك (zod)
```

- **server**: Hono على Node (أو Bun). Drizzle ORM مع PostgreSQL. التحقق من المدخلات بـ zod.
- **التخزين**: ملفات الحزم في تخزين متوافق مع S3 (مثل Cloudflare R2) خلف CDN. قاعدة البيانات تحفظ البيانات الوصفية فقط.
- **admin**: لوحة تحكم React + Ant Design، تتكلم مع `/admin/*` في نفس السيرفر.
- **التوقيع**: كل بيان (manifest) يوقَّع بمفتاح Ed25519. المفتاح الخاص لا يوضع على السيرفر العام، ويُوقَّع البيان عند النشر من اللوحة عبر خدمة توقيع منفصلة أو يدويًا بأداة CLI. المفتاح العام مضمّن في التطبيق.
- **النشر**: Docker image واحدة للسيرفر، واللوحة ملفات ثابتة. GitHub Actions للبناء والنشر.

### قاعدة البيانات (Drizzle)

| الجدول | المحتوى |
|---|---|
| `packs` | معرّف الحزمة (`qiraat-farsh`, `published-differences`, `riwayah-warsh-text`, `mushaf-layout-1405`…) ووصفها ونوعها |
| `pack_versions` | الإصدار، sha256، الحجم، مسار الملف، المصدر ورقم نسخته (مثل revision المستودع)، الحالة (`draft`/`published`/`revoked`)، ملاحظات التغيير |
| `channels` | `stable`، `beta`، `internal` |
| `releases` | ربط إصدار حزمة بقناة، مع أقل نسخة تطبيق تقدر تقرأه (`min_app_build`) |
| `app_versions` | لكل منصة: أحدث نسخة، أقل نسخة مدعومة، رابط المتجر، ملاحظات |
| `remote_config` | مفتاح/قيمة لكل قناة ومنصة ونطاق نسخ |
| `announcements` | عنوان، نص، رابط، فترة الظهور، القناة، الأولوية |
| `admin_users` | حسابات اللوحة (بريد + كلمة مرور مشفرة أو OAuth)، والصلاحية |
| `audit_log` | من نشر/سحب ماذا ومتى |

### الـAPI العام (بدون تسجيل دخول، للقراءة فقط)

| الطريق | الوظيفة |
|---|---|
| `GET /v1/manifest?platform=&build=&channel=` | البيان الموقّع: الحزم المناسبة لهذه النسخة بإصداراتها وsha256 وروابطها، والإعدادات، وأقل نسخة مدعومة |
| `GET /v1/packs/:id/:version` | تحويل لرابط الـCDN |
| `GET /v1/announcements?…` | الإعلانات الحالية |

- لا يُرسل التطبيق أي بيانات شخصية. لا حسابات للمستخدمين في هذه المرحلة.
- `ETag` و`Cache-Control` على البيان، وrate limit بسيط.

### API اللوحة (`/admin/*`، بتسجيل دخول)

رفع حزمة، التحقق منها، نشرها لقناة، سحبها، إدارة الإعدادات والإعلانات والنسخ، وعرض سجل التدقيق.

### صفحات لوحة التحكم (Ant Design)

1. الحزم: قائمة، إصدارات، رفع إصدار جديد (Upload)، فرق الحجم، الحالة.
2. القنوات والإصدارات: ما المنشور في كل قناة، ترقية من beta إلى stable بزر.
3. نسخ التطبيق: أقل نسخة مدعومة لكل منصة، ورسالة التحديث.
4. الإعدادات (Remote config): جدول مفاتيح مع القناة والمنصة.
5. الإعلانات: محرر، معاينة، جدولة.
6. سجل التدقيق.

### جانب التطبيق (Flutter)

- `UpdateService`: عند الفتح ومع وجود شبكة، يجلب البيان، ويتحقق من التوقيع، ويقارن الإصدارات.
- `PackStore`: ينزّل الحزمة في الخلفية، ويتحقق من sha256، ويخزّنها في مجلد التطبيق، ويبدّلها ذريًّا (atomic swap). الحزمة المضمّنة في التطبيق تبقى الاحتياطي دائمًا، وتعطّل أي حزمة تالفة يرجع التطبيق للمضمّنة.
- `QuranRepository.load()` يقرأ الحزمة المحدّثة إن وُجدت، وإلا المضمّنة.
- شاشة «التحديثات والمصادر»: إصدار كل حزمة ومصدرها وتاريخها، وزر تحديث يدوي، وخيار «التحديث عبر Wi-Fi فقط».
- إجبار التحديث: لو النسخة أقل من المدعومة، تظهر شاشة تحويل للمتجر.
- الإعلانات: بطاقة غير مزعجة تُغلق ولا تتكرر.
- الويب: نفس الآلية، مع تحديث قائمة Service Worker.

### أداة نشر البيانات

- `tool/publish_pack` تبني الحزمة من المصدر (مثل `import_qiraat_variants.py`)، وتحسب sha256، وترفعها كمسودة عبر API اللوحة.
- CI يتحقق أن الحزمة المضمّنة في التطبيق تطابق آخر حزمة stable.

### معيار الانتهاء

تعديل في الفرش يُرفع من اللوحة إلى beta، يظهر على جهاز تجريبي بعد فتح التطبيق دون نسخة متجر، ثم يُرقّى إلى stable. حزمة بتوقيع خاطئ تُرفض ويستمر التطبيق بالمضمّنة. التطبيق يعمل كاملًا دون شبكة.

## المرحلة 2: الروايات من المستودع

كل البيانات هنا من Quran Tajweed Engine كما هي، وتُنشر كحزم من المرحلة 1.

1. **صفحات شعبة وقالون بترقيم طبعتهما**: جدول (آية ← صفحة) من `data/mushaf/pages/<slug>.json`. صفحة 14 في شعبة تعرض آيات صفحة 14 في طبعة شعبة. تقسيم الأسطر داخل الصفحة غير متاح من المصدر، فيبقى النص متصلًا داخل الصفحة.
2. **إضافة الروايات الخمس التي لها نص موثق**: ورش، البزي، قنبل، الدوري، السوسي (`data/qiraat/qiraah-*.json`) مع خط `Qiraat.ttf` وجداول صفحاتها. تصبح قابلة للقراءة والبحث والعلامات.
3. **ربط الآيات بين الروايات**: اختلاف عدّ الآي (مثل البقرة 285 في ورش). لا يُعرض فرق إلا من الفرش. إذا لم يوجد ربط منشور بين عدّين، تُعرض الآية بترقيم روايتها دون مقارنة كلمة بكلمة.
4. **تنظيم قائمة الهامش**: الروايات العشرون مجمّعة تحت القرّاء العشرة، مع بحث داخل القائمة.
5. **الأصول (المد والإمالة والهمز…)**: حزم التجويد الخاصة بكل رواية في `data/tajweed-qiraat/` تُدرس أولًا: هل تصلح لعرض الأصول كما هي؟ لا تُعرض قبل التأكد من معناها في وثائق المستودع.
6. **التوجيه**: ملاحظات الفرش بالإنجليزية تحتاج إذن مؤسسة القرآن. الخطوة: مراسلتهم. أي توجيه عربي يُضاف لاحقًا يكون من مصدر منشور ومذكور.
7. **حزمة الفروق المعتمدة**: تبقى فارغة حتى يراجعها متخصص. اللوحة تدعم رفعها كحزمة عند توفرها.

معيار الانتهاء: الروايات الثماني قابلة للقراءة بترقيم صفحات طبعاتها، والهامش يعمل مع العشرين، ولا يظهر أي فرق غير موجود في المصدر.

## المرحلة 3: التلاوة

1. اختيار القارئ لكل رواية (حفص أولًا، ثم ورش وقالون إن وُجد مصدر صوتي مرخّص). قائمة القرّاء والروابط تأتي من الإعدادات البعيدة، فيُضاف قارئ دون نسخة جديدة.
2. تشغيل متواصل في الخلفية مع التحكم من شاشة القفل (`audio_service`).
3. تنزيل سورة أو جزء للاستماع دون إنترنت، مع إدارة المساحة.
4. تمييز الآية المقروءة في الصفحة إن توفرت توقيتات.

## المرحلة 4: تجربة القراءة والعرض

1. عرض صفحتين متقابلتين على التابلت والوضع الأفقي.
2. وضع قائمة الهامش في مكان ظاهر دائمًا.
3. طبعة 1441: إضافة تخطيط مصحف المدينة 1441 كحزمة ثانية عند توفر مصدر موثوق (مثل Quranic Universal Library)، مع اختيار الطبعة من الإعدادات.
4. اختبار الأسطر على مقاسات متعددة (موبايل صغير، كبير، تابلت، نص مكبّر).
5. سمات قراءة إضافية (بيج/سيبيا) وحجم واجهة.

## المرحلة 5: المكتبة والمتابعة

1. تصدير العلامات والملاحظات كملف ومشاركته، واستيراده.
2. ورد يومي ومتابعة ختمة بإشعارات محلية.
3. مشاركة الآية كنص أو صورة.
4. سجل القراءة وآخر المواضع.

## المرحلة 6: الجودة والإصدار

1. التجربة على أجهزة حقيقية: آيفون، أندرويد، والويب دون اتصال.
2. إعداد التوقيع والنشر على المتجرين، وأيقونة التطبيق وصفحات المتجر.
3. CI: تحليل، اختبارات، اختبار الأسطر الـ604، التحقق من الحزم، بناء الويب.
4. مراقبة الأعطال دون بيانات شخصية (اختياري، بعد موافقتك).
5. مراجعة التراخيص: KFGQPC للخطوط، MIT للمستودع، شروط Quran.com للفرش، ومصادر الصوت.
