## القواعد الثابتة (لا تُكسر)

1. **لا اجتهاد في القراءات.** كل فرق أو نص أو نسبة قراءة لقارئ يأتي من مصدر منشور مذكور، ويُعرض كما هو. لا محاذاة آلية تُعرض كفرق، ولا ترجمة أو تعليل من عندنا. المصدر الحالي: Quran Tajweed Engine (انظر `04-content.md`).
2. **التطبيق يعمل كاملًا دون إنترنت.** كل حزمة لها نسخة مضمّنة في التطبيق. السيرفر يحسّن ولا يُشترط.
3. **لا بيانات شخصية.** لا حسابات للمستخدمين ولا تتبع. طلبات البيان تحمل المنصة ورقم النسخة والقناة فقط. **الاستثناء الوحيد:** الإشعارات عبر OneSignal (D18)، وهي تنشئ معرّف اشتراك للجهاز داخل OneSignal. لا تُفعَّل إلا بعد موافقة المستخدم من شاشة شرح داخل التطبيق، ولا يُربط بها أي معرّف آخر (لا `external_id`، ولا بريد، ولا موقع)، والوسوم المسموحة فقط: `channel` و`platform` و`build` و`lang`. تُذكر في سياسة الخصوصية.
4. **كل ما يصل من السيرفر موقّع ومتحقق منه** قبل استخدامه. أي فشل في التحقق يعني تجاهل التحديث والاستمرار بالموجود.
5. **العقد قبل الكود.** تغيير شكل البيان أو الحزمة يبدأ بتعديل `01-update-protocol.md` ورفع رقم الصيغة، ثم السيرفر والتطبيق معًا.
6. **واجهة عربية RTL** في التطبيق ولوحة التحكم.

## المصطلحات

| المصطلح | المعنى |
|---|---|
| **حزمة (pack)** | مجموعة ملفات بيانات لها معرّف ثابت، مثل `qiraat-farsh`. |
| **إصدار حزمة** | رقم صحيح يزيد بواحد مع كل نشر لنفس الحزمة (1، 2، 3…). |
| **صيغة (format)** | اسم ورقم شكل محتوى الحزمة، مثل `qiraat-variants@1`. التطبيق يعرف الصيغ التي يقرؤها. |
| **البيان (manifest)** | رد السيرفر الموقّع الذي يقول للتطبيق: هذه الحزم المناسبة لك، وهذه الإعدادات والإعلانات والنسخ. |
| **قناة (channel)** | `stable` للجميع، `beta` للتجربة، `internal` للمطور. |
| **رقم البناء (build)** | الرقم بعد `+` في `version` داخل `pubspec.yaml` (حاليًا 1). يزيد مع كل نسخة متجر. |
| **مضمّن (bundled)** | النسخة الموجودة داخل التطبيق في `assets/`. |
| **مفعّل (active)** | النسخة التي يقرؤها التطبيق الآن: آخر حزمة منزّلة سليمة، وإلا المضمّنة. |

## طريقة العمل على أي مهمة

1. اختر مهمة من `ROADMAP.md` كل اعتمادياتها منتهية.
2. اقرأ الأقسام المرتبطة بها في هذا المجلد.
3. اعمل على `main` مباشرة (D20). لا تنشئ فرعًا.
4. نفّذ حتى يتحقق «شرط الانتهاء» المكتوب للمهمة، مع اختباراته.
5. إن اضطررت لقرار غير مكتوب: أضفه لسجل القرارات في نفس الـcommit، واذكره في رسالته.
6. قبل الـpush: `tool/verify.sh` يمر محليًا (D21). ثم commit رسالته تبدأ برقم المهمة (مثل `C-02: …`) وpush إلى `main`.
